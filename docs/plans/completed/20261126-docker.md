# Docker over vsock

The guest runs Docker and the Mac reaches it: a network on vmnet, a vsock device, dockerd in the guest and its socket on the Mac. Done when, on the test Mac, `lodka _vm` reaches Docker on its socket, `docker run` pulls and runs an image, fio runs in a container on a volume, and SIGTERM powers the guest off cleanly.

## Decisions

- The network is vmnet's shared mode through the macOS 26 API, which a process signed with the virtualization entitlement may start without root; vmnet gives NAT, DHCP and DNS. macOS 26's API ignores the interface id: each start gets a new MAC address and subnet. The guest probes the path MTU, as a network that drops full-size packets silently (the test Mac's, 1420) stalls TLS otherwise.
- Docker's API goes over vsock (lodka dials the guest's port 1025 for each connection), not TCP on the shared network, which every process on the Mac could reach.
- The control channel is a vsock stream the guest dials at boot (port 1024), with a line per message both ways: the Mac's clock and power off to the guest; its version, address and Docker coming up back. The clock is set again every 30 s, as it stands still while the Mac sleeps. One control connection is open at a time: a new one from the guest closes the one before.
- `lodka-guest` starts DHCP and dockerd and starts them again a second after they exit. On power off dockerd stops first, alone: it stops the containers, then containerd and its shims.
- SIGTERM asks the guest to power off and stops the VM after 15 s if it hasn't; a second signal stops it at once. A restart still stops the VM.
- The kernel is the one Docker, containerd and runc ask for: namespaces, cgroups v2, overlayfs, the bridge, iptables legacy and nft.

## Result

On the test Mac (M2, macOS 27), 4 vCPUs and 4 GiB: from `lodka _vm` to `docker info` in 0.50 s on the first boot, 0.89 s on the next; `docker run --rm alpine true` in 214 ms. fio on a volume, 4 KiB: random reads at depth 32 at 438k IOPS, random writes 232k, write and fsync 4.2k/s. SIGTERM powers the guest off in 1.1–1.2 s and removes Docker's socket; the volume is there on the next boot.
